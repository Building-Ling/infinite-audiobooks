# 无限有声书第一版实现任务

范围以 [第一版范围](v1-scope.md) 为准。按下面的依赖推进。每项都有可以现场检查的结果。

## 1. 跑通一段 PDF 到 MP3

依赖：无。真实调用需要 MiniMax API Key 和用于试读的中英文音色。

做一个可重复运行的入口，读取给定 PDF 和页码范围，只把选中页的正文交给 MiniMax Speech 2.8 Turbo，保存一份可播放的 MP3。页码从 PDF 文件第 1 页起算。章节转换长于单次请求时，按段落分批合成并按原顺序输出一份音频。

验收：用一本中文 PDF 和一本英文 PDF 各生成一段，确认正文范围和音色正确，记下耗时。越界或提不出文字时给清楚的错误，且不调用 TTS。用一个跨请求上限的范围验证拼接顺序。

## 2. 在网页上传、生成并播放

依赖：任务 1。

提供个人登录和书库。可以上传多本 PDF，给每本选语言，并设置一本当前书。先从书籍页按页码触发同一套生成流程，看到生成中、完成或失败。PDF、MP3 和片段记录保存在服务器上，播放页有可重复打开的地址。

验收：登录后上传两本书，切换当前书，发起一次生成并从书籍详情播放。重启应用后，书、当前书和已生成片段都还在。模拟一次合成失败，页面显示失败且可以重试。未登录访问片段链接时，登录后回到该片段。

## 3. 管理片段、复用和续听

依赖：任务 2。

在书籍详情列出已生成片段，支持播放和删除。按书、规范化后的范围、模型及音色复用成品。每个片段单独保存最近播放位置，播放中定期保存，暂停和离开时也保存。原链接和书库入口打开同一片段。

验收：听到某个位置后关掉页面，分别从原链接和书库重开，确认从最近保存的位置继续。切换另一片段时进度互不影响。重复请求返回原链接，MiniMax 调用次数不增加。删除后列表和原链接均无法访问该音频。

## 4. 在阿里云验证手机 HTTPS 播放

依赖：任务 2。可以与任务 3 并行。

把已有网页流程部署到现有阿里云轻量服务器，配置 HTTPS 和持久存储。部署前先确认当前 OpenClaw 服务和端口占用，以便安排部署路径。上线前需要一个手机能访问的 HTTPS 地址。

验收：关闭手机 Wi-Fi，用流量打开真实 HTTPS 链接，登录后能播放、拖动进度条。应用重启后链接仍可打开。记录这台服务器的生成耗时和手机实际播放体验。

## 5. 接入一个 Bot 渠道和书签章节

依赖：任务 3 和任务 4。开工前选定一个聊天渠道。

Bot 读取当前书，接受「读 PDF 第 42–48 页」和「读第 3 章」。章节从 PDF 书签定位，找不到时提示改用页码。确认收到后调用同一套生成流程，结束后回复可续听的 HTTPS 链接，失败时告知并允许重试。只接受个人账号的请求。

验收：从手机聊天里发出页码请求和一条可解析的章节请求，确认返回的链接能播放正确范围。没有当前书、章节找不到或生成失败时收到可操作的提示。重发已有请求时返回原链接，未授权账号无法发起生成。

## 6. 做一次隔天验收

依赖：任务 5。

验收：从手机流量实际点播一段中文和一段英文。任选一段听一会儿后退出，隔天从 Bot 原链接打开并确认续听，再到网页书库确认位置一致。记录从发消息到拿到链接的耗时，确认它符合日常使用预期。
